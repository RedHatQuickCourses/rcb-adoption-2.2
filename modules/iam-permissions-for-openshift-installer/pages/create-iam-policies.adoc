#  Create IAM Policies

= Create IAM Policies

The OpenShift installer requires specific permissions to provision and manage the necessary AWS resources for your cluster. These permissions are defined in AWS Identity and Access Management (IAM) policies. In this section, you will learn what permissions are required and how to create these IAM policies within your AWS account.

== Understanding OpenShift Installer Permissions

When you deploy OpenShift on AWS using the Installer-Provisioned Infrastructure (IPI) method, the installer (typically executed from a bastion host or your local machine) interacts with the AWS API to create a wide array of resources. These include:

*   **EC2 Instances:** For control plane (masters), worker nodes, and bootstrap nodes.
*   **VPC Components:** Such as VPCs, subnets, route tables, Internet Gateways (IGW), NAT Gateways, Security Groups, and Network Interfaces.
*   **S3 Buckets:** For storing bootstrap assets, OpenShift cluster manifests, and other cluster-related data.
*   **IAM Roles and Policies:** The installer creates roles and policies for the cluster's control plane and worker nodes, allowing them to interact with AWS services.
*   **Route 53:** For managing DNS records crucial for internal and external cluster access.
*   **Elastic Load Balancers (ELB):** Application Load Balancers (ALBs) and Network Load Balancers (NLBs) for cluster services.
*   **Elastic Block Storage (EBS):** Volumes for EC2 instances.

To perform these actions, the IAM identity used by the OpenShift installer must be granted appropriate permissions. While it's always recommended to follow the principle of least privilege, for the purpose of an initial deployment in a lab environment, we will create a comprehensive policy that covers all necessary permissions.

== Hands-On Activity: Creating the IAM Policy

You will now create a custom IAM policy in your AWS account using the provided JSON document.

=== Step 1: Navigate to IAM Policies

1.  Log in to the AWS Management Console with an administrative user.
2.  In the search bar at the top, type `IAM` and select *IAM* from the services list.
3.  In the IAM dashboard, navigate to the left-hand menu and click on *Policies*.

image::images/iam-policies-menu.png[IAM Policies Menu, 600] // Placeholder image reference

=== Step 2: Create a New Policy

1.  On the Policies page, click the blue *Create policy* button.

image::images/create-policy-button.png[Create Policy Button, 600] // Placeholder image reference

2.  On the "Create policy" page, select the *JSON* tab.

image::images/policy-json-tab.png[Policy JSON Tab, 600] // Placeholder image reference

3.  Copy the entire JSON policy provided above and paste it into the text area, replacing any existing content.

image::images/paste-json-policy.png[Paste JSON Policy, 600] // Placeholder image reference

4.  Click the *Next: Tags* button.

=== Step 3: Add Tags (Optional)

1.  (Optional) You can add tags to help organize and identify your IAM resources. For example:
    *   **Key:** `Environment`, **Value:** `Development`
    *   **Key:** `Project`, **Value:** `OpenShift`
2.  Click the *Next: Review* button.

=== Step 4: Review and Create Policy

1.  On the "Review policy" page, enter the following details:
    *   **Policy name:** `OpenshiftInstallerPolicy`
    *   **Description (Optional):** `Grants necessary permissions for the OpenShift installer to provision resources on AWS.`
2.  Review the policy summary to ensure it matches your intentions.
3.  Click the *Create policy* button.

image::images/review-create-policy.png[Review and Create Policy, 600] // Placeholder image reference

You have now successfully created the `OpenshiftInstallerPolicy`. This policy will be attached to an IAM role in the next section, which the OpenShift installer will then assume to perform its operations.
